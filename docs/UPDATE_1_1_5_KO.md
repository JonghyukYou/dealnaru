# 1.1.5 수집 요청 조절과 로그 요약

## 확인한 현상

- ITAD HTTP 429는 요청 한도 초과입니다. Retry-After 동안 기다려야 합니다.
- Steam HTTP 403은 접근 거부입니다. 이번에는 잠시 뒤 정상화됐으므로 반복 요청에 따른 일시적 제한일 가능성이 있지만 403만으로 정확한 원인을 단정할 수는 없습니다.
- ITAD HTTP 400은 별도의 요청 오류입니다. 단순히 수동 수집을 쉬는 것만으로 해결됐다고 판단하지 않습니다. 이제 제공자가 반환한 요청 오류의 메시지를 키·이메일·URL을 제외하고 표시합니다.

## 요청량을 줄인 부분

수동 Steam/ITAD 수집 완료 뒤 전체 게임 갱신까지 추가 요청하던 연결을 제거했습니다. 수동 수집은 해당 작업과 부족한 이력 예약만 수행하고 전체 갱신은 정기 일정 또는 명시적인 지금 갱신으로 실행합니다. 전체 갱신 중에는 대량 수동 수집을 409로 안내하며 겹쳐 실행하지 않습니다.

Steam 직접 조회는 기본 최소 1.6초, ITAD는 최소 1초 간격을 공유합니다. 429를 받으면 더 보수적으로 간격을 늘리고 Retry-After를 준수합니다. 대기 시간과 조절한 간격은 DB에 저장하므로 API 재시작으로 제한을 무시하지 않습니다. Steam 403 응답에 별도 대기 시간이 없으면 15분 후 다시 확인합니다. 이것이 원본의 제한이 반드시 15분 뒤 해제된다는 의미는 아닙니다.

이미 등록한 게임의 ITAD 현재가를 신규 메타데이터보다 먼저 확인합니다. ITAD에서 최근 10분 안에 확인한 KRW Steam 가격이 있으면 곧바로 같은 게임을 Steam에 중복 조회하지 않습니다. 원래 가격 관측 시각을 유지하며 재사용 때문에 새 가격 기록을 만들지 않습니다. Steam 직접 조회가 쉬는 동안에도 ITAD가 정상 응답하면 해당 Steam 구매처 가격이 갱신될 수 있습니다.

과거 이력 작업은 전체 현재가 갱신이 끝난 뒤 처리하며, 백그라운드 작업은 5분에 최대 20개씩 나눕니다. 인기 게임과 직접 요청한 게임을 먼저 확인합니다. 400/404 요청은 24시간 뒤 재확인하여 동일한 실패를 30분마다 반복하지 않습니다. 기존 가격 이력은 유지하고 요청 범위를 몰래 줄이거나 이력을 만들어 넣지 않습니다.

## 로그 화면

| 표시 | 의미 |
| --- | --- |
| 완료 | 해당 작업이 정상 종료됨 |
| 일부 완료 | 일부 가격/출처는 확인됐고 나머지는 확인 필요 |
| 요청 대기 | 요청 한도 또는 일시적인 원본 장애로 대기 |
| 접근 제한 | 401/403 등 원본의 접근 거부 |
| 요청 확인 | 400/404 등 요청·게임 정보 확인 필요 |
| 실패 | 분류하지 못한 실행 오류. 실제 앱/DB 오류도 포함 |

같은 출처·같은 오류 유형은 한 시간 단위로 묶고 반복 횟수와 가장 최근 메시지·시각을 보여줍니다. 429 발생 후 나머지 전체 갱신 단계도 함께 대기하며 같은 실패 배지를 단계마다 쌓지 않습니다. 기본 화면은 실행 요약이며 전체 상세 로그와 확인 필요한 작업을 선택할 수 있습니다. 기존 로그의 원래 status는 보존하고 알려진 HTTP 원인은 표시 상태로 구분합니다. 실제 앱 오류를 성공으로 바꾸지 않습니다. 최근 72시간 보관 규칙은 유지합니다.

## 적용

배포용 ZIP의 apply_update.py는 파일 버전을 확인하고 DB·코드·직전 API 로그를 백업한 다음 수정 파일을 반영합니다. API 시작 시 source 대기 상태 테이블과 재시도·로그 묶음용 열을 비파괴적으로 추가합니다. 게임·가격·회원 데이터를 초기화하지 않습니다. 일일 백업 예약이나 Resend 키도 변경하지 않습니다.

수동/자동 수집이 진행 중이라면 완료된 뒤 적용합니다. 적용 후 관리자 화면에서 Ctrl+F5를 누릅니다. 대기 중인 출처는 표시된 재확인 시각까지 기다리고 같은 작업을 연속으로 요청하지 않습니다. PC의 기존 로컬 백엔드도 같은 ITAD 키로 자동 수집 중이면 종료하고 운영 서버 한 곳에서 수집합니다.

새 400 로그에 제공자의 메시지가 나오면 그 내용을 확인해 요청 매개변수 또는 게임 연결을 추가로 수정할 수 있습니다. 외부 원본의 접근 거부를 이 업데이트가 해제한다고 보장하지 않으며 IP·프록시를 돌려 제한을 우회하지 않습니다.
