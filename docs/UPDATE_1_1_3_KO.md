# 딜나루 1.1.3 — 배포 준비·GitHub 링크

2026년 11월 19일 기준.

- 하단의 가격 출처 문구를 제거하고 링크 이름을 “GitHub 저장소 ↗”로 변경했습니다. 출처 설명은 README에 정리했습니다. 기존 환경 설정 `VITE_REPOSITORY_URL`에 실제 저장소 웹 주소를 넣으면 링크가 표시됩니다.
- Google 검색 등록을 생략하는 배포 안내로 바꾸고 HTML·Caddy에 noindex를 적용했습니다. 사이트맵과 robots.txt의 사이트맵 주소는 제거했습니다. URL 직접 접속은 가능합니다. 공개 GitHub 저장소의 검색 노출은 별도입니다.
- [배포 안내](DEPLOYMENT_KO.md)를 GitHub 브라우저 업로드 → 서버 Git clone → 운영 설정 → 실행 → 데이터 수집 순서로 다시 작성했습니다. 최신 개인정보 설정 두 항목과 배포 후 Git pull·백업·재빌드 절차를 포함합니다.
- 배포 형식 검사는 이전의 고정 도메인·사이트맵 안내 대신 실제 도메인 형식을 검사합니다.

## 적용

처음 배포한다면 위 배포 안내를 처음부터 진행합니다. 이미 실행 중이라면 기존 환경 파일과 DB를 유지하고 변경한 소스를 반영합니다. 서버 루트 `.env`의 `VITE_REPOSITORY_URL`에 실제 GitHub 주소를 입력한 뒤 `sudo docker compose up -d --build web`으로 웹을 다시 빌드합니다. 로컬 개발에서는 `frontend/.env.local`의 값을 채우고 개발 서버를 다시 시작합니다.

별도 DB 초기화나 신규 환경 변수는 필요하지 않습니다. 이번 ZIP에는 1.1.2의 중고나라 전용 수집·JetBrains 가격 수정과 이전 개선도 포함합니다. 아직 GitHub 저장소가 만들어지지 않았으므로 임의의 실제 주소는 넣지 않았습니다.

## 확인 범위

- 프런트 프로덕션 빌드 성공. 산출물에 실제 설정 경로로 주입한 검증용 저장소 URL·GitHub 링크 문구·noindex가 반영되고, 이전 하단 출처 문구와 사이트맵이 없는 것을 확인했습니다. 검증용 주소는 배포 소스의 기본값으로 넣지 않았습니다.
- 운영 설정 검사기에서 올바른 도메인 2건, 잘못된 도메인 5건, 개인정보 필수 항목 누락 2건, 안전하지 않은 저장소 URL 2건, 발신 도메인 불일치 1건의 기대 결과를 확인했습니다.
- 배포 안내의 운영 설정 항목, 실행 경로, 로컬 문서 링크와 Bash 명령 구문을 검사했습니다.
- 서버 생성·메일 발송·공개 도메인 접속과 실제 Docker 컨테이너 실행은 이번 검증에 포함되지 않았으며 운영 환경에서 확인해야 합니다. 브라우저 화면 검증은 수행하지 않았습니다.
