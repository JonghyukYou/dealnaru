# 딜나루 1.1 적용 안내

기존 1.0 원본을 보완한 소스입니다. **이번 작업은 파일 수정이며 운영 사이트에 자동 배포하지 않았습니다.** 기존 회원·찜·알림·게임 DB를 초기화할 필요가 없습니다.

## 바뀐 내용

| 요청 | 반영 내용 |
| --- | --- |
| 프로그램·AI 확대와 가격 | 20개 제품·68개 활성 요금제. Midjourney·ElevenLabs·Descript·Obsidian·DaVinci Resolve·LibreOffice 추가. 결제 방식·통화·예산·무료 요금제 필터. 공식 가격 구조·비교표·이스케이프된 JSON 파싱과 날짜 표시 보강 |
| 할인 예측 | 최근 가중 주기, 중앙값·MAD 이상값 완화, 월별 패턴 보조, 예상 날짜 범위·할인율 범위, 순차 검증 평균 날짜 오차, 자료 참고 점수와 예측 보류 |
| 약관·개인정보 | 이용약관 13개 조항, 개인정보 처리방침 12개 항목. 수집·보유·파기·위탁·국외 이전·권리 행사 안내. 비밀번호 확인 후 직접 탈퇴. 만 14세 이상 가입 확인 |

가격 점검일은 2026년 11월 19일 한국 시간입니다. 실제 공식 페이지 응답에서 **54개 요금제의 가격을 확인**했습니다. **9개는 과거 확인 가격**, **5개는 금액 미확인**입니다. ‘금액 확인 필요’를 없애려고 추정 가격을 넣지는 않았습니다. [가격 출처 점검 결과](PRICE_SOURCE_AUDIT_KO.md)에 제품별 결과가 있습니다.

## 먼저 할 일: 기존 파일 보관

1. 실행 중인 사이트 폴더를 다른 이름으로 복사해 보관합니다. 예: `DealNaru-before-1.1`.
2. 현재 사용 중인 `.env`, `backend/.env`, `frontend/.env`를 따로 보관합니다. 이 파일에는 DB·메일 연결 정보가 있으므로 인터넷이나 GitHub에 올리지 마세요.
3. pgAdmin에서 사용하는 DB를 선택하고 `Backup…`으로 백업합니다. 현재 DB 이름·계정·비밀번호를 새 임의 값으로 바꾸지 마세요.
4. 수정본 ZIP을 새 폴더에 풉니다. 안의 `dealnaru`가 프로젝트 폴더입니다.

## Windows에서 개발 서버로 실행하는 경우

1. 기존 백엔드와 프런트 터미널에서 `Ctrl+C`를 눌러 서버를 멈춥니다.
2. 수정본의 `backend`, `frontend`, `docs`, `deploy`와 루트 설정 파일을 기존 프로젝트에 반영합니다. **기존 실제 `.env` 파일과 DB는 유지**합니다. ZIP에는 실제 비밀 설정·DB·설치 폴더가 없습니다.
3. 백엔드 터미널에서 실행합니다.

   ```powershell
   cd backend
   venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   uvicorn app.main:app --reload
   ```

   가상환경 이름이 `venv`와 다르면 현재 사용 중인 환경을 활성화하세요. 없으면 `py -m venv venv`로 만든 뒤 진행합니다.
4. 별도 터미널에서 실행합니다.

   ```powershell
   cd frontend
   npm ci --include=dev
   npm run dev
   ```

5. 터미널에 표시된 프런트 주소로 접속합니다. 새 제품과 요금제는 백엔드 시작 시 기존 DB에 추가됩니다. 같은 상품이 매번 중복 생성되지 않습니다.
6. **`python -m app.seed --reset`은 실행하지 마세요.** 버전 업그레이드 명령이 아니며 회원과 수집 데이터를 지웁니다.

## Docker로 운영 중인 경우

1. 먼저 위의 파일·DB 백업을 합니다.
2. 새 소스를 운영 저장소에 반영하고 실제 `.env`는 유지합니다.
3. 루트 `.env`에 아래 공개 안내 값을 추가합니다. 프런트 빌드 때 사이트 화면에 들어가는 값이므로 비밀번호를 넣지 마세요.

   ```dotenv
   VITE_PRIVACY_OFFICER=실제 개인정보 업무 담당자 또는 부서명
   VITE_OVERSEAS_NOTICE=실제 국외 이전 현황과 법적 근거, 거부 방법 안내
   ```

   `VITE_OVERSEAS_NOTICE`에는 실제 계약을 확인한 뒤 이전받는 자·연락처, 국가, 항목, 목적, 시기·방법, 보유 기간, 법적 근거, 거부 방법·영향을 적습니다. 임의의 국가나 보유 기간을 쓰지 마세요. 국외 이전이 없으면 실제로 없다는 내용을 적습니다.
4. 기존 `VITE_OPERATOR_NAME`, `VITE_SUPPORT_EMAIL`, `VITE_HOSTING_NOTICE`, `VITE_MAIL_NOTICE`, `VITE_RETENTION_NOTICE`도 실제 운영 현황과 맞는지 확인합니다. `VITE_RETENTION_NOTICE`에는 백업 보관 기간과 삭제 반영 주기도 적습니다.
5. 서버의 프로젝트 폴더에서 실행합니다.

   ```bash
   docker compose config --format json | python3 deploy/check_config.py
   docker compose up -d --build
   docker compose ps
   ```

6. 상태가 정상인지 보고 회원가입·로그인·기존 찜·새 가격 화면을 확인합니다. DB 볼륨은 유지하며 `docker compose down -v`를 실행하지 마세요.
7. 약관 1.1과 변경 내용을 실제 이용자에게 고지합니다. 기존 회원의 과거 동의 기록은 임의로 1.1로 바꾸지 않습니다.

## 공식 가격을 다시 갱신하는 방법

관리자로 로그인 → `관리` → `프로그램·AI` → `공식 혜택 갱신`을 누릅니다. 요금제의 가격·통화·청구 주기를 확인해 저장하고 실패한 항목은 과거 값과 확인 날짜를 보존합니다.

터미널에서도 할 수 있습니다. 백엔드를 한 번 시작해 테이블을 만든 뒤, 같은 가상환경과 `.env`로 실행하세요.

```powershell
cd backend
venv\Scripts\Activate.ps1
python -m app.software_price_cli status
python -m app.software_price_cli refresh
```

`status`의 `current`는 최근 공식 확인 가격, `last_confirmed`는 과거 확인값, `unavailable`은 금액 미확인입니다. 자동 갱신이 켜져 있어도 외부 출처의 차단·가격 카드 변경까지 해결된다는 의미는 아닙니다.

- Notion의 현재 공개 응답은 USD였습니다. 새 USD 요금제는 자동 원화 환산하지 않습니다. 기존 KRW 요금제는 과거 확인 금액으로 남깁니다.
- Adobe·Canva는 동적 가격이나 응답 제한으로 이번 자동 확인에 실패했습니다.
- Google AI와 JetBrains 가격 수집은 최신 수정본에서 보강했습니다. [최신 적용 안내](UPDATE_1_1_2_KO.md)를 확인하세요.
- 연간 금액은 1년 전체 결제액입니다. 월 환산액은 별도 표시합니다.

## 중고나라 수집

현재 버전은 중고나라만 지원합니다. 최신 변경은 [1.1.2 적용 안내](UPDATE_1_1_2_KO.md)를 확인하세요.

1. 출처의 수집·재게시 조건을 확인한 뒤 `USED_MARKET_ENABLED=true`를 설정합니다. Docker 운영 기본값은 꺼져 있습니다.
2. 관리자 → 중고마켓에 `엘든링, 젤다`처럼 쉼표로 구분한 검색어를 최대 10개 입력합니다.
3. 키워드당 수집 개수를 1~20개로 설정하고 수집합니다. 출처 선택·지역 설정은 없습니다.
4. 중고 거래 페이지에서 검색하면 수집된 중고나라 검색 결과 전체의 최저가와 동률 매물을 강조합니다. 가격순 정렬도 사용할 수 있습니다.
5. 출처에서 HTTP 403 등 접근 제한을 반환하면 원인과 중단 단계를 표시합니다. 이때는 공식 검색 링크에서 확인합니다.

가격은 배송비 제외, 수집 당시 판매중 기준이며 상품 상태·플랫폼·구성품 차이는 별도로 확인해야 합니다.

## 약관·개인정보 화면

- `/terms`: 가격 표시, 예측의 의미, 최저가 범위, 중고 거래와 외부 판매처, 이용 제한·책임·탈퇴를 안내합니다.
- `/privacy`: 처리 항목·목적·보유 기간을 표로 보여주고 위탁·국외 이전·쿠키·권리 행사와 담당자를 안내합니다.
- 로그인 후 개인정보 처리방침의 회원 탈퇴에서 현재 비밀번호와 삭제 확인 항목을 입력하면 계정·찜·알림·모든 로그인 세션을 운영 DB에서 삭제합니다. 다른 회원과 게임·상품 데이터는 유지합니다.
- 탈퇴는 외부 서비스의 구독 취소가 아닙니다. 메일 제공자 로그와 백업의 처리 현황은 실제 계약·운영 정책에 맞게 공개 안내를 채워야 합니다.
- 가입 화면과 운영 API에서 만 14세 이상 확인을 받습니다. 생년월일·신분증을 추가로 수집하지 않습니다.

법령과 실제 구현을 기준으로 문안을 보완했지만 운영자의 계약·서버·담당자 정보를 대신 확정할 수는 없습니다. 공개 운영 전에 실제 값과 변경 고지 절차를 확인하세요. 참고: [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1006185717), [2026 개인정보 처리방침 작성지침](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20885).

## 검증 결과와 범위

- 프런트 프로덕션 빌드 성공.
- 실제 공식 가격 페이지에서 54개 가격 파싱 확인. 9개 과거 값과 5개 미확인은 구분했습니다.
- 이 환경의 미리보기 연결 서비스가 실행되지 않아 브라우저 화면·모바일 실화면 검증은 수행하지 못했습니다.
- 운영 PostgreSQL·SMTP/Resend 실제 발송·운영 배포는 실행하지 않았습니다. 기존 사이트에 적용한 뒤 운영 환경 점검이 필요합니다.
